# 切换 HTTP 模拟与真实 CLI -p

添加 **Claude Code 请求插件（3.2.0-beta.1）** 后，同一个接口可选择两种运行模式；Windows x64 桌面版还可直接在界面中管理随包服务。这里添加的是 NextChat 请求插件；真实 CLI 模式使用本机已安装的 Claude Code。旧版插件包和接口绑定保留，不自动迁移。

1. 设置 → **请求扩展插件** → **Claude Code 请求插件** → **添加插件**。出现“已添加”表示此版本已可使用。
2. 编辑一个 Anthropic Messages 接口，在“请求扩展插件”中选择 **Claude Code 3.2.0-beta.1**。
3. 在 **运行模式 / Mode** 中选择“独立 HTTP 模拟”或“真实 Claude Code CLI（-p）”，填写该模式的配置并保存。

**从文件导入其他插件**用于添加他人提供或从 NextChat 导出的请求插件 JSON 包。使用随软件提供的 Claude Code 请求插件时无需导入文件，也无需重新安装本机 CLI。

| 模式                       | 发包者                 | 所需组件                                     | 工具执行             |
| -------------------------- | ---------------------- | -------------------------------------------- | -------------------- |
| 独立 HTTP 模拟（默认）     | 固定构建的独立网络组件 | 随包 `nextchat-wire-relay.exe`               | NextChat 工具与 MCP  |
| 真实 CLI（`-p / --print`） | 安装的真实 Claude Code | 随包组件与本机 Claude Code，无需另装 Node.js | CLI 自己的工具与 MCP |

界面只展示当前模式的字段，隐藏另一模式时不会清除它的配置。HTTP 版本标记和实际 CLI 版本分别保存，两个服务的地址、令牌和 beta 配置也分别保存；接口网关地址、API Key、模型与认证方式共用。切换模式并保存后，后续请求使用新模式；已经开始的请求继续使用启动时的配置。

## 桌面界面启动（推荐）

1. 便携版先完整解压，再双击 `NextChat.exe`。保留同目录的 `claude-code-tools` 文件夹；安装版自动部署这些文件。
2. 按上方步骤安装并绑定 **3.2.0-beta.1**。网关地址、API Key 和供应商模型名仍填写在接口本身。
3. 选择 **独立 HTTP 模拟**，点击 **启动并连接**。软件会在后台启动随包服务、分配本机端口并自动填写服务地址和令牌，HTTP 模式不需要 CLI 文件。
4. 使用 **真实 CLI（-p）** 时，会自动查找本机 `claude.exe`；也可点击 **选择程序** 指定。点击 **启动并连接** 后，桥接地址、令牌和实际 CLI 版本自动填入，再保存接口。
5. 可随时查看运行状态、点击 **停止服务**。退出 NextChat 时，它启动的服务及子进程会一起关闭。再次打开软件后，在需要使用的接口中重新点击 **启动并连接** 并保存。

同一个 NextChat 实例中的接口共用对应模式的服务；停止服务会影响使用它的其他接口。重新启动服务会更换端口和令牌，其他接口点击 **使用此服务** 即可更新配置。切换模式不会自动停止另一模式的服务。管理按钮只控制当前 NextChat 实例创建的进程，手动或远端部署的服务仍可直接填写地址连接。

本版随包管理支持 Windows x64。CLI 模式调用真实 `--print`，无需用户打开终端；它不是交互式 PTY 会话。HTTP 版本标记可配置，真实 CLI 模式的版本必须与所选文件一致。

## 网页部署或手动启动 HTTP 模式

```powershell
$env:NEXTCHAT_WIRE_TOKEN = '替换为至少16字符的随机令牌'
& ./build/nextchat-wire-relay.exe
```

在 HTTP 模式填写相同令牌，默认服务地址 `http://127.0.0.1:8789`。此模式不加载 CLI 文件，详情见 [独立发包组件](wire-relay.md)。

## 网页部署或手动启动 CLI -p 模式

Windows x64 随包组件内含桥接运行时，也可手动启动：

```powershell
$env:NEXTCHAT_BRIDGE_TOKEN = '替换为至少16字符的随机令牌'
$env:NEXTCHAT_CLAUDE_PATH = 'C:/Users/你的用户名/.local/bin/claude.exe'
& ./claude-code-tools/nextchat-wire-relay.exe --bridge
```

从源码部署或需要自定义多版本驱动时，继续使用 Node.js 桥接：

```powershell
claude --version
$env:NEXTCHAT_BRIDGE_TOKEN = '替换为至少16字符的随机令牌'
node scripts/client-bridge.mjs
```

在 CLI 模式填写实际 CLI 版本、相同令牌和默认桥接地址 `http://127.0.0.1:8788`。桥接服务每次核验真实版本，随后启动 `--print`、以 `stream-json` 输入输出；`-p` 是 `--print` 的短选项。这是非交互式调用，不启动交互式终端会话。额外 CLI beta 留空时采用 CLI 默认值，CLI 模式的模型列表需要手动添加。

CLI 路径、多版本映射、工作目录及工具配置见 [CLI 桥接说明](request-plugins-legacy.md)。HTTP 模式不要求启动此服务；CLI 模式不要求启动独立 HTTP 服务。缺少当前模式的组件或版本不匹配时会报错，不自动切换另一模式。

网页模式由 NextChat 部署服务器连接上述服务，桌面版由本机连接；网页版的 `127.0.0.1` 指部署服务器。工具由所选模式对应的执行器管理，切换模式不会迁移 CLI 内部的工具状态或签名历史。已有聊天仍作为上下文传递；不满足原生续接条件时，CLI 创建新的原生会话。
